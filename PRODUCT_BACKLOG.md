# Product Backlog

## How to read this backlog

This initial backlog captures the product-owner vision and its stated system areas. Entries are high-level until decomposed into implementation stories. “Approved” means the capability is part of the supplied product requirements; it does not mean work is scheduled or implemented. “Proposed” identifies supporting implementation ideas or unresolved details. Testing is **Not started** unless evidence is recorded.

Priority is a suggested planning priority: **P0** = discovery/foundation dependency, **P1** = core learner journey, **P2** = important ecosystem capability, **P3** = later capability. These priorities require confirmation during MVP planning.

Priorities are provisional. Dependencies identify product or technical prerequisites, not a commitment to a specific implementation sequence. The proposed milestone order is in [DEVELOPMENT_ROADMAP.md](./DEVELOPMENT_ROADMAP.md). Update status and testing evidence as work proceeds; retain deferred ideas with a reason rather than silently removing them.
